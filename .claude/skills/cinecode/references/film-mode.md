# Film mode

The six steps with a gate at each, research, per-shot revisions and a layered sound design. Read with `SKILL.md` (first questions, routes, hard rules) and the purpose file.

## 1. Context and revision protocol (mandatory)

Full rules: `references/context-protocol.md`. In short:

1. **Who does the work.** This chat talks with the user, keeps `STATE.md` and does the work it holds the context for (a short film's roadmap, script, shot list and picture, notes of up to five targeted edits). A **fresh subagent** takes an independent part that runs beside it (sound, narration takes, research, the independent viewer) or a chapter of a long film (`context-protocol.md` §1), with its model named and a brief built by `python3 tools/brief.py <kind> --task "…" --writes "<its own files>" --reads "…" --done "…"` (it quotes the kit's rules for that kind of task: sound, music, voice, picture, sourcing, script, roadmap, review, revision; the guard stops a helper started without one) plus the files it needs (`STATE.md`, the shot's row in `shots.json`, `notes/round-N.md`), never from chat history. Helpers take one task and at most 25 tool calls, write details to files and reply in ≤ 10 lines (what changed, paths, PASS/FAIL, next decision). The chat keeps decisions and paths only; at most one downscaled contact sheet per gate.
2. **Notes.** Save the user's notes verbatim in `notes/round-N.md`, split them per shot; up to five targeted edits this chat makes itself, more go to one subagent per affected shot (parallel when independent); unaffected shots are never touched.
3. **Diagnose before rebuild.** A helper first reproduces a defect with 1–3 test frames or measurements and writes the root cause; then the smallest fix. A failed fix is diagnosed again before the next attempt (the next helper gets the diagnosis file, never the failed chat); a second rebuild of the same issue needs the user's OK with its estimated cost.
4. **Handoff.** At every gate (with `Pace: through`, only when the guard reports a large chat, and then the new chat starts without a question), and after about 15 user messages or when the guard reports a large chat: update "Resume here" in `STATE.md`, save a silent snapshot (`python3 tools/snapshot.py "<step>"`), and offer the new chat as `templates/HANDOFF.md` says: where a tool can start it (the Claude Code desktop app), the user only says yes and it opens already told to continue; elsewhere the one line to paste, **"STATE.md'den devam et"** · **"Continue from STATE.md"**.
5. **Models.** Every helper starts with the model and effort its brief names (`context-protocol.md` §5): taste and judgement on the chat's own model, fixed-recipe work lower, measuring by script.
6. **Budget meter** in `STATE.md`: running estimate per phase against the profile's ceiling; stop and ask at 80%; state the estimate before any whole-shot rebuild.

**From a saved format** (`SKILL.md` routes; `init_film.py <short-name> --format <name>` without `--quick`): read `FORMAT.md`; the interview asks only the idea (and the length when it differs); look, type, finishing, sound identity, camera character, transitions and rhythm come from the format and stand in the roadmap's director card as "format: …". The scenes are written new.

## 2. The six steps

| # | Step | Output | Gate |
|---|---|---|---|
| 1 | Interview (one round of questions, in three calls) | `INTERVIEW.md` answers, `STATE.md` fields | answers or "ok" |
| 2 | Roadmap | `ROADMAP.md` (concept, shots with times, counted by length: `references/craft.md` §0, look, sound identity, hook, risks) | **user OK** |
| 3 | Script and text | `SCRIPT.md`, `shots.json` | **user OK** |
| 4 | Style frame | one still at final quality: `review/style-v1.png` | **user OK** |
| 4b | Type direction | 3 specimen cards on the style frame's look → the film's type spec (`TYPE` roles) | **user pick** |
| 5 | Animatic | `renders/animatic-v1.mp4` (low-res, timed, temp sound) | **user OK** |
| 6 | Render, sound, final | `renders/film-v1.mp4` + poster frame | deliver |

**Pace** (asked with the script gate, `SKILL.md`: The pace of production is the user's): with `Pace: through` in `STATE.md` the steps after the script run on without their STOP: each choice goes to the ★, the style frame and key stills are shown as progress, the voice and the music are never the ★: their candidates are played and the user picks them by ear, at any pace (`SKILL.md`), and the draft cut is the next gate. A step starts after the previous gate. Notes from the user are applied **only to the affected shots, lines or layers**; everything else stays identical. Each gate message: what was made, the file path, one precise question, your recommendation. Update `STATE.md` and save a silent snapshot at every gate (`python3 tools/snapshot.py "gate <n>"`).

## Step 1: Interview

**What the brief settled is never asked.** A brief that fixes the beats skips the interpretations question; a brief that names the look, the sound or the length skips those; no follow-up reads the brief back for confirmation. A complete brief (`SKILL.md`, A complete brief goes straight to work) skips the interview, the roadmap and the script gates: the card goes into `STATE.md` and the first gate is the key stills or the draft.

Read `references/steering.md` first and point the idea's interpretations as it says. Use `templates/INTERVIEW.md` (the copy in the project): **one round, six questions, in this order** (the question tool takes four questions a call): call 1 = the idea's interpretations (Q1), length and format and the medium (Q2, two questions; the medium as in `quick-mode.md` §1, 1a, written in `STATE.md` as `- **Medium:**`, and the guard holds the board until it is there); then the direction board is built for the picked interpretation and sent to the user; call 2 = the style (Q3) first and alone about the board, then tone and references (Q4); call 3 = voice and music, the sound identity (Q5) and the profile (Q6). Without the tool: the same order in messages. each with options, one marked ★ (recommended, with a few words why) and always "your own answer".

1. **The user's idea first**, as free text. If they already gave one, offer 2-3 interpretations of **that** idea (one ★), after the prediction test (`python3 tools/brief.py predict --task "<their message>"`: a helper lists what anyone would make of it), the sparks (Deal before proposing, below) and the overlap check (`python3 tools/brief.py overlap --task "<their message>"`: a helper marks the candidates that repeat a prediction or one of this user's films; `writing.md` §1). Only if they say "no idea / suggest" ("fikrim yok / sen öner") offer 3 ideas.
2. **Length and format** (15 s / 30 s vertical / 60 s / 1–3 min 16:9 / 3–8 min in acts / square / own; the ★ is the length this idea needs, with a reason). Every count after this (shots, chapters, research, film stills) follows the length (`references/craft.md` §0).
3. **Style: three directions authored for this film (the direction board).** All three sit inside the medium chosen at Q2. Most of the look is invented for this story; one of the three rows may be a library recipe when one truly fits it (`styles.py suggest`, its poster in the row), never the whole board. With a reference video, its measured form is row R of the board (`references/reference-video.md`). Start from the six references `python3 tools/deal.py deal look` deals from about 190 (cinematographers, directors, photographers, painters, studios, movements, crafts) and build the three that serve this story from them. Each direction is your own: a name of its own; one sentence of what the film looks like and why that serves this story; its devices (the light and its source, a palette of 4–5 hex, texture and grain, lens and camera, type); and 3–4 pictures of the highest quality that carry it, picked by light and frame, never by topic: stills from films (a title gives stills from across that one film; search 6, keep the ones that show the light, `quick-mode.md` §1b; every search started at once as its own background shell call (`run_in_background`) with `--max-wait 12`: `python3 tools/asset_search.py search --sources filmgrab --n 6 --max-wait 12 --q "<film>" --out research/dir-a1`, one per film, about 20 s for six; a title FilmGrab does not hold is swapped for another film, never searched again; the supply probe runs beside them, never before), a cinematographer's or photographer's work, paintings from open art collections (`--sources aic,met`) for a painterly light, and the user's own `refs/`. For a film that informs (a documentary, an explainer, a story of facts, a film without a narrator), one of the three is led by motion design: its devices named by job (`motion-design.md`), its references from title sequences and explainers. The three differ in kind and in tone, never three shades of one: not all three in the dark, not all three without colour; at least one in daylight or in colour unless the story happens only at night (`direction.py board` says ONE TONE). A look the user named is read by you first (`quick-mode.md` §1, question 3). Build one image, a row per direction with a measured palette (`direction.py board --row "A|<name>||<folders>"`, `references/looks.md` §10; mood only, never in a frame), send it before the question (`SendUserFile`, render), and ask: A, B, C (★ first, with its reason) · "see a proof frame of each first" · from my references (`refs/`) · own. **Proof frames,** when chosen: one frame of this film's own subject in each direction (its key moment, not a sample scene), built quickly from the engine's presets with the direction's palette and light, three side by side; then the pick. Never three frames that could belong to another film.
4. **Tone** (three words) and references: the user's own (`refs/`), and whether the kit searches open sources (★ search and show one board with the roadmap · only my own · skip; one more round on request at any gate, without using a revision round).
5. **Voice and music** (music may be the user's own song or track: then the picture follows its beat grid, `references/music-video.md`; a found recording is picked by ear from 2–3 candidates played to the user, `references/sound.md` §8), plus a **light sound identity**: three one-line sound concepts tailored to the idea; the user picks or edits one (`references/sound.md` §1).
6. **Profile in words only:** Quality / ★ Balanced / Economy. Never show money amounts.

The ★ of Q5 follows the purpose file (Cinematic: an ambience-led identity; Ad & product: narrator + music). With Ad & product, one follow-up asks for the purpose file's inputs (subject facts, brand colours and fonts, logo, call to action, own footage).

**Deal before proposing** (keeps proposals fresh from film to film): run `python3 tools/deal.py deal spark`, `deal angle` and `deal sound` (the sparks: `quick-mode.md` §1, question 1). Each deals 3 options from its bank, seeded by date and project, leaving out options this project already used (`history.json`). For each category pick one from this film's facts and log it with a one-line reason: `python3 tools/deal.py pick angle <id> --reason "…"`. The look is dealt as references (`deal look`, Q3) and its three directions are authored for this film from them. A film through several worlds deals one seed for each (`deal.py deal seed --n <worlds>`, `quick-mode.md` §2). The angle pick joins the ten loglines of the writer prompt (step 1) and shapes Q1's interpretations; the sound pick is a springboard rewritten into one of Q5's three concepts. A new hand needs a written reason: `deal.py redeal <category> --reason "…"`. The user's own answer always decides (`pick <category> own --reason "…"`).

Show the defaults once (the user accepts with "ok" or changes lines): GPU browser pipeline; subtitles none unless asked (max 2 languages, stacked, in a safe area); on-screen text allowed by format; faces allowed when needed (stylise or silhouette suggested for close-ups); **hook rule: the first 2 seconds move from frame 1**.

Write the answers into `INTERVIEW.md` (Source: user / accepted ★ / default) and set `Profile`, `Format`, `Look`, `Subtitles` in `STATE.md`.

## Step 2: Roadmap (STOP)

Research for the roadmap starts with the supply probe and stays in its 15-minute box (`quick-mode.md` §1b); with a real person, team or event the probe's numbers and the routes reach the user before the roadmap. Fill `ROADMAP.md`, one screen: logline, the turn (before / after), the ending and how it re-reads the opening, why it works in code and how the subject itself is on screen at every key beat (the Code fit line, `quick-mode.md` §2: when no real material shows it, as with prehistory, the future or the imagined, it is built for the film; stand-ins never carry it); the shots with times (count by length, `references/craft.md` §0: 4–8 for 30 s, grouped by chapter over 60 s and by act over 3 min), the subject's action, camera and the read of each; the look (base preset + changes); the sound identity expanded (palette, signature sound, silence, voice, music); the hook (what moves on frame 1); top 3 risks; the **specificity test** (`references/writing.md` §12): mandatory in full for the Ad & product purpose (8–12 subject-only facts, the one-sentence concept, the competitor swap), a light world test for a cinematic film; the purpose file's defaults (Cinematic: lens character and grain in the look, the finishing passes chosen at the style frame; Ad & product: labels, end card, variants); for a place, product, brand or promo piece also the names that appear on screen (labels or lower thirds in the film's type, `craft.md` §4). Close it with the **director card** (`references/quick-mode.md` §2): the direction picked on the board with its reason, camera character, motion spring word, tempo (energetic, standard or contemplative, the ★ from this story with a reason, the average shot length and the shot count it gives), transitions, sound identity; type and finishing are chosen later (steps 4b and 4), so they read "at step 4b" / "at the style frame". If the user gave only a bare idea, open with the 2-3 interpretations (the three angles kept by the writer prompt, steps 1-4) and recommend one. With "search" at question 4, run the light research first (`references/quick-mode.md` §1b) and show its board beside the roadmap; with "only my own", the board of `refs/`; with "skip", none. **Wait for OK.**

## Step 3: Script and text (STOP)

**The text first, the shot list after the OK.** A film about a real person, place or event gathers `research/facts.md` first (`writing.md` §16). Follow the WRITER PROMPT (`references/writer-prompt.md`) and fill `SCRIPT.md`: the narration, the on-screen text, the key moments, the thesis line in 2–3 wordings asked on its own, and the ending (`writing.md` §15). **A cold read before it is shown:** once the script is written, a fresh helper (`brief.py review`, model inherit) gets only its lines and on-screen text, nothing else, and writes `review/script-cold.md`: what happened in order, and every place it had to guess (a thing never named, a cause never given, a line left hanging, `writing.md` §8). Fix those in the script, then show it; the gaps a cold viewer finds are cheap in words and dear after the voice is recorded.

**The whole script at once, shown in full:** it is written in one go, never act by act, and the gate message carries every line: the narration and the on-screen text in order, under the act headings for a long film, with the word count against the budget (a link to `SCRIPT.md` is not showing it; the guard holds a script question the user has not read). The gate asks two questions in one call: the script (OK · one note) and the pace of production (`SKILL.md`). The user approves words, so nothing else waits for them: `shots.json` (from `KIT/templates/shots.example.json`: narration in each shot's `vo`, on-screen text in `text_on_screen` (a shot's own, in shot seconds; words that span beats, as in a one-shot film, in the film-level `text_on_screen` list, in film seconds), the subject's action in `action`, every camera as a line in `camera.move.line`, from `references/camera-moves.md`) is written **after** the text is approved, from the locked text, and `python3 tools/validate_shots.py shots.json` runs until it has no errors; the shot list goes to the user only if it changed the text. Show the user: logline, the turn, beat sheet, the lines (or "wordless") with the word count against the budget, on-screen text, one line on why this angle. **Wait for OK.** After the OK, changing a line means re-timing the animatic.

The WRITER PROMPT is in `references/writer-prompt.md` (mandatory for every story, script, narration line or on-screen text).

## Step 4: Style frame (STOP)

1. Measure the picked direction (`direction.py measure`, `references/looks.md` §10) and apply its look patch (palette, light, post, and the finishing devices this scene takes: `references/finish.md`) to a copy of the chosen preset in `engine/looks.mjs`, the film's own look (new id); when the picked board row is a library recipe or the user named one, read only `KIT/styles/<id>.md` and carry its colour logic, materials, motion and camera grammar into the look (`references/looks.md` §9); then build the film's most important moment in `engine/scene.html` (or `engine/index.html` for a shader-only world). `references/looks.md`. For a realistic or material look this frame meets the realistic-render standard (`references/looks.md` §5): real scanned textures/HDRI first, its render time reported (near or under a second a frame at full size, else cut the costly effect without lowering the look), and every later scene meets the same bar, not this frame alone.
2. With "from my references": contact sheet of `refs/`, palette measured, light and finish read, then a custom preset (`references/looks.md` §4).
3. Render **one still** at final size: `node tools/capture.mjs --url engine/scene.html --out review/style-v1 --start <f> --end <f> --params "look=<id>&w=<W>&h=<H>"`, then copy its one PNG to `review/style-v1.png` (`cp` in bash, `Copy-Item` in PowerShell); every later step reads that file.
4. Cold self-review on a 768 px thumb (`python3 tools/qc.py thumb …`), after `direction.py compare` against the picked direction: composition, light, palette, readability at phone size; next to the references if there are any; against the visual cliché table (`references/looks.md` §8). **Style serves the subject:** heavy stylisation lives in backgrounds and secondary layers; the subject's silhouette and key features stay readable (`looks.md` §5). Judge only what is on screen (not the intention or the code), in these steps, and repeat them at every later self-review:
   - **One-second read, on the subject:** the subject and the shot's single idea land at a glance.
   - **Squint test:** on a tiny copy (`qc.py thumb … 96`) the light and value structure and the composition still hold.
   - **Consecutive shots** (from the animatic on, on the contact sheet): no two adjacent shots share size, angle and value.
   - **Phone check** for 9:16, 1:1 and 4:5: one clear subject at phone size (`qc.py phone`).
   Fix up to two rounds yourself before showing it.
5. Show the still (path, one line on the look) with two questions in one call: the gate (OK · one note) and the **finishing**, a multi-select, all off by default: motion blur (fast shots; their render time × 6–8) · print tone (lifted blacks, filmic roll-off) · gate weave (a slight projector drift) · none ★ (`references/purpose-cinematic.md` §2). Print tone changes the still, so when it is chosen, re-render the still with `post.print` once and show it; motion blur gets its one-shot test before the final render. The choice goes into the film's look and `STATE.md`. **Wait for OK.** The approved still is the bar for every later frame.

## Step 4b: Type direction (STOP)

`references/typography.md` §10: type references following the references answer of the interview ("search": the user's `refs/type/`, then `asset_search.py search --type typography` from Fonts In Use, Art of the Title, Typewolf, Are.na; "only my own": `refs/type/` alone; "skip": no type references, the deal still runs) on one board → `type_extract.py measure` on the strongest + your own visual read → `deal.py deal type --purpose <…> --look <look id> --title "<working title>"` → one **specimen card per pairing** with the approved style still behind it (`--params "…&still=../review/style-v1.png"`) at the deliverable aspect → the user picks with the question tool (three pairings + own); log it with the reason (taste log). The chosen roles go into the `TYPE` block of every engine page with `check.strings` and `check.sizes`; one `LICENSES.csv` row per family.

## Step 5: Animatic (STOP)

Narration if the film has a voice, in two parts, never one: **first the user picks the voice by ear**: `tts.py --audition` renders 2–3 candidates reading one line (and `voice_treat.py audition` 2–4 treatments of the chosen one), the coordinator shows each as its own file and asks one question; a helper may render the takes but never picks, and nothing more is generated until the user has chosen. **Then** the lines from `SCRIPT.md` with `python3 tools/tts.py --lines audio/vo-lines.json --out audio/vo` in the chosen voice and treatment. Check the engine's quota against the line count before starting (a free tier can stop after a few lines: say so at the pick, with the cost of the other engine) (the key once, `keys.py`; without a key, Turkish lines offer EMA Lightning, free and offline, as a choice: about 800 MB once, installed only if picked, `tts.py --install ema`, then `--engine ema`; the OS voice only as a temp, `writing.md` §9), each line given the film's own voice with `voice_treat.py` (`sound.md` §4b) → `audio/vo-t/`; measured line lengths → shot timing in `shots.json`. Then:

```bash
python3 tools/animatic.py shots.json --out renders/animatic-v1.mp4 --stills review/stills [--vo audio/temp_vo.wav]
# --vo only for a narrated film: the treated lines laid at their times into one WAV with mix.py; a wordless film leaves it out
python3 tools/qc.py sheet renders/animatic-v1.mp4 2 6
```

Ask one question: "Is the pacing right? Any shot too long or too short?" **Wait for OK.** With `Pace: through` the animatic is still made, without the question: `python3 tools/make.py check renders/animatic-v1.mp4` measures the ending's time and the pace report from the script's timings; fix what it finds in the shot list before any full render.

## Step 6: Render, sound, final

1. **Draft cut first:** build the shots (item 2) and the sound (item 3) at draft quality first: shots at half size as the profile says, joined and laid on the mix as `renders/draft-v1.mp4`, checked with `python3 tools/make.py check renders/draft-vN.mp4` (the Quick draft checks on this cut: the hook, darkness, blank frames, stillness and repeats, rhythm, the sound floor, ready sounds and sync; it writes logs/check-draft-vN.txt and the guard holds a cut shown without it; fix what it holds; what is left as it is goes to the user with the cut, one plain line each, what, where and why, and the user decides; never only a line on the roadmap's card), then the silent one-sentence test (`engine.md` §4: a fresh helper sees only its small sheet and says what the film is about; a miss is fixed first). A story over about 3 minutes also gets the **cold comprehension test** on the cut: a fresh helper that knows nothing about the subject gets only the narration transcript and the sheet and writes in `review/comprehension-vN.md` what happened, who did what and why, the order of events, and what stayed unclear or felt like a jump; every unclear point is a red item before the draft is shown. With a narrator, the first line comes within 2 s in any film over a minute (`writing.md` §14; `make.py` names it NARRATION LATE). One question: final, or notes (notes are applied to drafts). The full-size render and the master start only after the OK.
2. **Picture:** every shot at full detail from the draft cut on (`quick-mode.md`: Half size, never half detail), with the finishing devices that serve it and none that hurt it (`references/finish.md`, named per shot); a true story is told with its **real material first**: archive photographs, documents, the real places, footage the licence allows (`assets-and-licences.md`); generated or stock pictures fill only what does not exist. Every stock shot passes the **relevance test**: it shows this story's people, era, place or object, never a generic stand-in; a shot that would fit any other film is replaced or cut. Code-made pictures next to real footage are either photoreal (real PBR materials, path-traced or composited onto a real plate) or plainly stylised (motion design, documents, diagrams), never in between. Violence in a real case is implied: one memorable aftermath image, never bodies, never the real victims' death images. Two shots cut from one plate or one scene continue the camera move, the light and any flicker across the cut (the second starts where the first ended, never reset to its own start: a reset reads as a glitch). Build each shot in the approved look, with only the devices the roadmap's director card names (light, signature, transitions); check a still per shot against the style frame before rendering it; render shots in the background with a status file (`references/engine.md` §2); encode per shot, concat.
3. **Sound:** first the picture-event audit (`references/sound.md` §5, `review/sound-audit.md`: every on-screen event with its synced, layered sound); then build the layers from the chosen identity on the master principles (`references/sound.md` §0, then the sections it points to): bed per space, low body, textures, foley, hero moments, voice (treated as the film's own, §4b, `voice_treat.py`), signature sound, music if chosen; mix with `tools/mix.py`; master with `tools/master_audio.py` (−14 LUFS, ≤ −1 dBTP) muxed onto the picture.
4. **Check:** `python3 tools/qc.py hook` must PASS (hard rule), then `python3 tools/qc.py all`, `qc.py action` and `qc.py sceneloud` with the shot boundaries (subject action, loudness and harshness per shot); the purpose file's gates and checks; a looping film also `qc.py loop` (the last frame flows into the first); the cold review against the style frame; the final checklist in `references/engine.md` §5.
5. **Before the final, offer a jury check** (`references/jury.md`: six pinpoint questions and three fixes; the user chooses; the chosen fixes are a notes round).
6. **Deliver** (`SKILL.md` Hard rules: Delivery): the film copied to the project folder as `<title>.mp4` with its path first, duration, format, a poster frame (`review/poster-v1.png`), the 3 weakest shots with timestamps and why, the listening note, the credits file (`python3 tools/make.py credits` writes `<title>-credits.txt`; tell the user to paste it into the video's description or the post's caption, never on the picture), and the one-line offer to keep the format (`formats.py save`, `quick-mode.md` §8), asked after the clean-up question, each on its own (`SKILL.md` Hard rules: versions without clutter). For X, Slack or Discord, also a copy with the poster on frame 0 (`craft.md` §7). **For YouTube** (a long film), the package beside the film: a thumbnail at 1280x720 (`<title>-thumbnail.jpg`, the film's strongest image with at most three words, readable at 160 px wide), `DESCRIPTION.md` (two hook lines, chapter timestamps from the act or chapter starts when the film has them, the sources and credits from `LICENSES.csv`), the subtitles as `.srt` per language and the subtitled copy when asked.

## Notes from the user

Ask for notes in **one batch per round** (timestamps help). **What the user praised is locked:** each round's file starts with a keep list (their words: "açılış planı çok iyi", "ortadaki tempo tam oldu"), and a fix or a re-plan may not change those parts; a re-plan is written as a diff against the praised version (KEPT · CHANGED · NEW, each change with the note it answers), so nothing that worked is lost on the way. Save them verbatim in `notes/round-N.md`, split them per shot, line or layer; up to five targeted edits this chat makes itself, more go to one fresh subagent per affected shot (`references/context-protocol.md` §2); defects get a diagnosis first (§3). Change only those, re-render only the affected shots (re-encode them alone and concat again), and reply note by note: done / done differently because… / open because…. Each round makes a new version (`film-v2.mp4`); after the user's OK on the final, only the delivered film and the last two versions are kept (`SKILL.md` Hard rules: versions without clutter). A note that adds shots or changes the total length is a **re-plan**: update the roadmap and shot list, show them with one still per new or changed shot, and wait for OK before any render.

## Profiles (in words)

| | Quality | Balanced (default) | Economy |
|---|---|---|---|
| Shots | the top of the length's range (`craft.md` §0), richer scenes | the middle of the range | the bottom of the range, simpler scenes |
| Style frame rounds before showing | up to 3 | up to 2 | 1 |
| Drafts | half size for every shot | half size for moving shots | one draft cut at 720p or half size, whichever is smaller |
| Sound | full layer stack, recorded material where it helps | core layers + signature | bed, hero moment, voice/music |
| Self-review | every shot, two passes | every shot, one pass | the hook, the style match, the final |

## Tools and subagents

In Cursor and Claude Code the protocol (§1) runs with subagents (Cursor: Task/subagent; Claude Code: the Agent tool; both inherit the chat's model unless one is named; a new chat for the handoff); Quick mode builds and revises in the main chat and uses helpers only for the prediction test, the overlap check, narration takes and the independent viewer (`quick-mode.md` §6). In a tool without subagents, keep the same files, do one task per chat and hand off at every gate. In Cursor the skill works from `~/.cursor/skills/` or `<project>/.cursor/skills/`, or by asking "follow KIT/SKILL.md".
